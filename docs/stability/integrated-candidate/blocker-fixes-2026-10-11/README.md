# PR40 prioritized blocker fixes

The integration candidate now addresses the selected-recipient file relay, truthful delivery, first-use and changed-identity trust handling, and SSH-safe guest restore. This is an integration review candidate; it does not qualify a stable release or paid one-click hosting.

## Final implementation

- File data carries explicit selected recipients. Empty targets never broadcast. Both peers must support delivery receipts, be authenticated and share a channel. Server-provided admission responses are distinguished from peer errors; outbound server-only fields are refused. Selected recipient IDs are removed before forwarding.
- A bounded local queue refusal or shared server budget refusal retains the same encrypted chunk and index for retry. Server admission charges all selected deliveries atomically. A bounded token bucket replaces the file-specific rolling meter and limits credit after long idle periods. Client jobs share credit and rotate after dispatch, including while awaiting confirmation. Synchronous confirmation and cancellation cannot overwrite the job state.
- An upload finishing is Verifying, not Delivered. Authenticated recipient receipts follow complete AEAD/Merkle/size verification. All receipts are needed for Delivered; missing receipts preserve confirmed/unconfirmed recipient counts as PartiallyDelivered. Password waiting has a separately bounded deadline.
- Production sender authorization rechecks the selected peer, identity, channel, connection and live trust storage before content. New peers require safety-number verification; changed keys and unavailable trust storage fail closed. Prompt requests have immutable tokens and serialized asynchronous dialogs. A conditional identity reset cancels only that peer's prompts and jobs, retaining unrelated Ready files and prompts. A multi-recipient job containing the reset peer is cancelled as a whole.
- Historical restore accepts and verifies the configured SSH port before enabling its dropping firewall. Resume state binds that port. Modern encrypted restore validates archived SSH and server ports and the matching firewall rule before mutation. Ready publication requires pinned TLS/protocol readiness and a stable service, including after backup restart.
- Feature-disabled builds exclude file-sharing configuration widgets and guard runtime cleanup. Qt/GCC rate and timer integer types are explicit. Existing tests, file sizes, recipient-selection assertions and timeouts were retained.
