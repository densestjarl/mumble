# Received-save trust and duplicate-save correction

Source `5eadce0753b634147f97746e192ddef613019a02` checks the authenticated received name/key against the current saved identity immediately before queueing a save. Removed, changed or unavailable trust blocks that request. Missing/unavailable trust uses a confirmation error; only a changed key emits the changed-key warning. Worker abort cleanup retains the useful failure.

An in-flight save guard ignores duplicate requests until the worker reports Ready or a terminal outcome. An earlier authorized save is reported truthfully, and rejection state is cleared on terminal outcomes. A revocation after authorized queueing does not newly cancel that write.
